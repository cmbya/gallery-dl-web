# Instagram 订阅与飞牛任务计划

## 首次使用
1. 升级前等待下载结束，停止应用后备份 `/vol2/1000/docker/INS-NET/data` 全目录，尤其 Cookie、原归档和SQLite文件。不要将备份上传到仓库。
2. 从当前检出源码使用 `docker compose -p ins-net up -d --build`。单独复制仓库主Compose并无backend/frontend源码，不能直接构建；远程构建版需将build.context改为fork指定提交子目录。
3. 网页打开“订阅管理”，添加用户名或主页链接。各博主分别设置追更检查数量、历史新增数量及两种开关。
4. “设置”中导入Instagram完整Netscape Cookie。仅已配置不代表有效；可手动在线检测，登录与帖子查询分别显示。检测不下载媒体，会请求Instagram，受冷却限制。
5. 先对单个博主低额度试运行。真实游标跨时间恢复、平台当前可用性及标题目录需在本机验收，自动测试不能代替真实测试。

## 两条飞牛定时任务
任务计划软件中选择可执行Shell脚本的任务类型，使用有Docker权限的执行身份。不在脚本里写Cookie。

追更：
```sh
docker exec ins-net-backend-1 python -m gallery_dl_web.automation trigger refresh
```

补历史：
```sh
docker exec ins-net-backend-1 python -m gallery_dl_web.automation trigger history
```

不需要cd项目目录。两种模式读取网页保存的启用博主和数量。返回accepted只代表入队，最终下载结果看订阅管理的运行记录。暂停退出码为2，连接或提交失败为1；不要在飞牛设置失败后无间隔无限重试。

## 内容和去重
- 只遍历posts列表，不单独遍历Reels；列表中视频仍下载。
- 追更检查N条，历史目标新增完成N条；一帖多图必须全部完成才计一条。预算、失败或历史不足可能使新增不足目标，会报告原因。
- 去重按成功记录，不因手动删文件自动重下。旧文件不导入，可能再次下载一次。显式重新下载只重置目标记录，不自动删除旧文件。
- 新内容目录为 `instagram/用户名/文案首行_帖子ID/媒体`，无文案用无标题，已定目录保持稳定。
- 429、明确会话失效、安全验证会暂停自动任务，后续定时不继续请求。解决后手动恢复；检测成功不自动恢复。
- 历史游标失效时显示“需重新定位历史进度”，不会自动无限回扫。等待 Instagram 任务结束（或先取消该用户排队/运行任务），点击订阅卡片的“重新定位历史进度”并确认；也可向 `POST /api/automation/subscriptions/{id}/reposition` 发送 `{}`。仅将历史游标重置到头部、状态改为等待补全，不清除帖子/媒体归档、待重试记录或已有文件，也不会立即启动下载。下次手动或定时历史补全从头扫描，受原有扫描/请求/时间预算限制并跳过已归档帖子；预算耗尽后需另一次触发才能继续。Instagram 锁占用或该用户有排队/运行任务时返回 409，等待结束后重试。不要删除数据库来强行恢复，否则丢失去重记录。

## 部署边界
仅适合可信内网；原应用没有因此获得完整登录鉴权，不要暴露公网。Docker默认bridge与links沿用现有要求，重建后前端应同步重建以更新链接。
