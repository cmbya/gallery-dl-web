# 自动订阅限速与异常暂停

仅适用于订阅管理的 refresh / history（含页面立即触发和外部定时触发），两种模式独立保存至现有 SQLite state。普通手动下载保持旧机制，不被自动订阅全局暂停强制禁用；自动暂停期间不要重复手动测试。

全局控制新增请求最小/最大间隔（默认 5/10 秒）、媒体间隔（默认 3 秒）、博主最小/最大间隔（默认 60/120 秒）。这些默认仅是保守起点，不保证避免平台限制。PATCH `/api/automation/pacing` 支持按模式部分更新；拒绝未知字段、空值、布尔、字符串、非有限数、负数、超过 1800 秒及最小值大于最大值。读取 `/api/automation` 可核对 `pacing` 和 `next_run_at`。

任务开始时冻结配置，修改下一任务生效，不缩短已有博主等待。所有实际发送经过共享节流器，包括主页、API、详情、安全检查允许的规范化跳转以及媒体下载。媒体间隔与请求间隔取较晚的允许发送时间，不重复叠加上游 sleep；归档/已存在文件跳过不单独睡眠。等待不扣请求次数，但任务内部等待计入原有 1800 秒硬超时（仍遵循服务器有限配置），大间隔可能使任务提前达到时间上限，不无限延长任务。

每次任务结束（含取消/失败）记录下一允许执行时间，同一博主不同模式也不能绕过。等待期间不持有 Instagram 锁，任务保持 queued 并附带等待信息，可取消、暂停、关闭服务。重启保留时间；以单调时钟限制单次等待最多 1800 秒，避免时钟回拨无限延期。重新获得锁后复查订阅开关、取消、暂停及批次余额。

429 / challenge / invalid_session 继续全局暂停；自动任务 `redirect_home`、`redirect_login`、`redirect_challenge`、`redirect_unsupported` 也保守暂停，原始 reason 保留，界面称“异常跳转，疑似限制”，不宣称已确认风控。跨域、非法协议等仍显示准确安全原因，未放宽目标验证。Cookie 检查身份接口仅跳首页而帖子可访问（或未测试帖子）不误暂停；帖子接口异常仍暂停。

更新 Cookie、检查成功、重启均不会恢复暂停，须显式恢复。恢复后仍使用原批次额度，已完成文件、部分媒体记录、游标和待办保留；中止任务可再次触发续跑。外部 fnOS 定时配置不作修改。日志仅输出固定分类，不写 URL、query 或 Cookie。

验证均使用临时数据库、离线 Requests 适配器和假时钟；不向 Instagram 发送请求，也不代表实网解除风控验证。
